# Golang 求职学习计划（12 周）

> 目标：先具备可面试的通用 Go 后端能力，再根据反馈选择方向。  
> 默认投递范围：业务后端 / 云与基础设施 / 云原生平台。

---

## 总目标

12 周后你能：

- 独立用 Go 做可上线的后端服务
- 讲清并发、HTTP、数据库、常见故障
- 简历上有 **1 个完整项目** + Terraform Provider / IaC 相关经历（如有）

---

## 每周固定节奏（全程通用）

| 事项 | 建议 |
|------|------|
| 编码 | 每天 1.5–3 小时，周末可翻倍 |
| 算法 | 每周 4–6 题（数组 / 哈希 / 链表 / 树 / 双指针） |
| 输出 | 每周写 1 篇短笔记（踩坑 / 设计决策） |
| 检查 | 每周日复盘：完成了什么、卡在哪 |

---

## 第 1–2 周：把 Go 写熟

### 学

- 语法、接口、错误处理、`context`
- goroutine / channel / `sync`（Mutex、WaitGroup、Once）
- 标准库：`net/http`、`json`、`io`、`testing`

### 做

- 不用框架，手写一个小 HTTP API（CRUD + 中间件日志）
- 给关键路径写表驱动测试，跑一次 `-race`

### 验收

- 能解释：何时用 channel、何时用 mutex
- 能排查简单的 data race

---

## 第 3–4 周：Web 服务成型

### 学

- Gin（或 Echo）路由、中间件、参数校验、鉴权（JWT）
- 配置管理、结构化日志
- MySQL 基础 + GORM（或 `database/sql`）
- Redis 基础（缓存、过期、简单锁）

### 做（主项目启动）

做一个「任务 / 工单 / 短链」任选其一：

- 注册登录、CRUD、分页
- MySQL 持久化
- Redis 缓存热点读
- Docker 一键启动

### 验收

- `docker compose up` 能跑
- 接口文档（简单 README 即可）清晰

---

## 第 5–6 周：工程化与可靠性

### 学

- 超时、重试、幂等、限流（概念 + 简单实现）
- 优雅关闭、健康检查
- 单元测试 / 集成测试边界
- `pprof` 基础（看 CPU / 内存）

### 做

- 给主项目加：请求超时、统一错误码、优雅退出
- 模拟下游超时，验证 context 取消是否生效
- 补 2–3 个关键路径测试

### 验收

- 能说清一次请求从进入到 DB 的完整路径
- 能定位一个简单性能问题（哪怕是人造的）

---

## 第 7–8 周：分布式常见能力

### 学

- gRPC + Protobuf（会做一个 Unary RPC）
- 消息队列选一个：Kafka 或 RabbitMQ（生产者 / 消费者、至少一次投递）
- 常见坑：重复消费、乱序、消息堆积

### 做

- 主项目加一个异步能力：例如「创建后发通知 / 写审计日志」走 MQ
- 额外写一个很小的 gRPC 服务，被主服务调用

### 验收

- 能画一张：同步 API + 异步链路的架构图
- 能解释「至少一次」下如何做幂等

---

## 第 9–10 周：云原生与差异化

### 学

- Docker 再扎实一点（多阶段构建、镜像瘦身）
- K8s 基础：Deployment / Service / ConfigMap / 探针
- 可观测：日志 + metrics（Prometheus 了解即可）

### 做（结合已有优势，任选其一）

- **A.** 把主项目部署到本地 K8s（kind / minikube）
- **B.** 写一篇「Terraform Provider 开发经验」总结（资源生命周期、幂等、重试、API 错误处理）
- **C.** 做一个很小的 Operator / 控制器 demo（可选，有余力再做）

### 验收

- 面试能讲 10 分钟：资源创建 / 更新 / 删除与错误重试如何处理

---

## 第 11–12 周：面试冲刺

### 学 / 练

- 八股：Go 调度、GC 粗略、GMP、channel 常见题
- MySQL：索引、事务隔离级别、慢查询思路
- Redis：缓存穿透 / 击穿 / 雪崩、数据结构适用场景
- 网络：TCP 握手、HTTP / HTTPS
- 项目深挖：瓶颈、故障、决策与取舍

### 做

- 模拟面试 3 次（项目讲解 + 并发题 + SQL 题）
- 简历压到 1 页：项目尽量量化（QPS、延迟、故障恢复等）
- 刷近 2 年常见 Go 面试题清单（不必全背，要能展开）

### 验收

- 项目介绍 3 分钟版 / 10 分钟版都顺
- 至少准备 2 个「线上问题或难点」故事

---

## 12 周后的默认岗位定位

先投这三类（范围最广）：

1. Go 业务后端
2. 云厂商 / 基础设施 / DevOps 偏研发
3. 云原生平台（有 K8s / IaC 更吃香）

有面试反馈后再收窄，不必现在选死。

---

## 资源原则（少而精）

- 官方文档 + 《Go 程序设计语言》或同等入门书（一本就够）
- 框架 / 库只看官方文档和示例
- 算法用 LeetCode 热题 + 分类刷
- 项目优先「能讲清楚」，不要堆技术名词

---

## 第 1 周立即执行清单

1. 用标准库写一个带中间件的 HTTP CRUD
2. 加上 `-race` 测试
3. 每天 1 道简单算法
4. 整理最熟的 1 个业务 / 资源流程，写成「创建 / 读 / 更新 / 删除」口述稿

---

## 能力清单速查

### 语言与工程（必会）

- 接口、错误处理、`context`、并发原语
- `go.mod`、项目结构、单元测试、`-race`、`pprof`

### Web / 微服务（多数岗位核心）

- HTTP 服务、鉴权、限流、超时
- Gin / Echo / Fiber（会一个即可）
- gRPC + Protobuf
- MySQL / Redis
- 日志与基础可观测性

### 分布式（中高级加分）

- 消息队列（Kafka / RabbitMQ / RocketMQ 至少一种）
- 幂等、重试、熔断、一致性、分布式锁
- Docker、K8s 基础

### 计算机基础（面试常问）

- 数据结构与算法（中等难度即可）
- 操作系统、网络、数据库原理常识
