# Golang 后端求职计划（4 周冲刺版）

适用人群：0-6 个月/转行、目标岗位为后端业务开发、优先本地城市、期望 4 周内拿到 Offer。

---

## 1. 目标与衡量标准

### 目标

- 4 周内拿到 1-2 个可选 Offer（优先本地城市）
- 让简历具备“可筛选通过”的表达
- 具备支撑面试的能力闭环：基础题能答、项目能讲、现场能写

### 每周衡量（建议记录在表格/看板）

- 投递量：第 1 周 30-50；第 2 周 60-100；第 3-4 周 100+
- 面试量：每周至少 2 场（不够就加投递/换渠道）
- 项目里程碑：每周都有可展示的新增能力点
- 复盘闭环：每场面试当日完成复盘并在 48 小时内补齐短板

---

## 2. 总体策略（优先级从高到低）

- 作品集优先：做 1 个能跑、能讲、能扩展的主项目（比做多个半成品更有效）
- 面试友好：选后端业务高频组件（HTTP + MySQL + Redis + 鉴权 + 基础工程化）
- 以战养战：从第 1 周就开始投递，用面试反馈迭代简历、项目和准备方向
- 少而精刷题：保证常见题型能写出并讲清楚，不追求题量

---

## 3. 主项目建议（用于简历的“拳头项目”）

推荐做一个「业务 API 服务」：例如待办/记账/简易电商后台/博客 API。

### 必须包含（面试最常问）

- 用户体系：注册、登录、JWT 鉴权、中间件
- 业务模块：至少 2 个资源（例如 task、tag / order、product），支持 CRUD + 分页
- MySQL：表结构、索引设计（至少 2 个索引能讲清为什么建）
- Redis：做 1 个读多接口的缓存（并能说明缓存策略与失效方式）
- 工程化：统一返回结构、错误码规范、日志、配置分环境
- 可运行：README 写清启动方式（最好提供 docker-compose）

### 加分项（选 1-2 个做到可讲）

- 幂等（例如创建请求用 idempotency-key）
- 限流（简单 token bucket 或固定窗口都可以）
- 简单异步任务（例如发消息/写审计日志/延迟处理）
- 基础测试（3-5 个单测，覆盖 service/工具函数）

---

## 4. 四周执行计划

### 第 0 天（今天完成，2-4 小时）

- 选定本地城市 20 个 Go 后端 JD，提取关键词（Gin/HTTP、MySQL、Redis、Linux、Docker、微服务等）
- 输出“可投递版”简历（1 页优先），并准备一个可分享的 GitHub 仓库
- 建一个投递看板（表格即可）：公司、岗位链接、投递时间、状态、反馈点、跟进时间

### 第 1 周：可面试基础 + 项目立项落地

目标产物：

- 主项目仓库搭建完成并能跑通核心链路
- 简历完成第 1 次优化（贴合 JD 关键词、项目描述可追问）
- Go 基础与后端基础问答能“说顺”

执行要点：

- Go 基础（每天 1-2h）：slice/map/channel、interface、并发基础、context、常见坑
- 后端业务基础（每天 1-2h）：HTTP/REST、鉴权、错误码、参数校验、分页
- 主项目（每天 2-3h）：完成登录注册、JWT、中间件、1 个业务模块 CRUD
- 投递（每天 5-10 个）：拿市场反馈，迭代简历表达

### 第 2 周：项目工程化 + 让简历有亮点

目标产物：

- 主项目具备缓存、分页、基础分层与统一规范
- README 完整（启动、配置、API 示例、目录结构）
- 形成项目“3 个可讲难点”的讲稿

执行要点：

- 数据库与索引：为核心查询补齐索引，能用 EXPLAIN 解释
- Redis 缓存：至少 1 个接口做缓存，并定义失效策略（TTL/主动失效）
- 工程化：配置分环境、日志（带 request-id）、统一错误码、基础测试 3-5 个
- 刷题（每天 30-60min）：数组/字符串/哈希/双指针/二分/栈队列为主
- 投递（每天 10-20 个）：开始“跟进 + 复投”

### 第 3 周：补短板（Linux/Docker/部署）+ 高频模拟面试

目标产物：

- 项目可 docker-compose 一键启动（服务 + MySQL + Redis）
- 完成至少 3 次模拟面试（可自己录音复盘）
- 10 组高频题答案能稳定输出

执行要点：

- Linux 常用排障：top、ps、lsof、ss、curl、tail、grep、日志定位
- Docker：Dockerfile、compose、环境变量、端口、数据卷
- 稳定性概念：超时、重试、限流、熔断（能讲原则与取舍）
- 面试模拟：按“自我介绍 1 分钟 + 项目深挖 10 分钟 + 基础快问快答”练习
- 投递（每天 10-20 个）：保持面试密度

### 第 4 周：冲刺拿 Offer（高密度投递 + 针对性补齐）

目标产物：

- 简历与项目进入稳定状态，只做针对性优化
- 复盘文档成型（题目分类 + 标准答案 + 自己的项目对应点）
- 面试节奏跑通：约面-准备-复盘-跟进

执行要点：

- 投递（每天 20-30 个）：本地优先，其次周边/通勤可接受
- 按 JD 定向准备：Redis/微服务/消息队列/性能优化等，补“能聊的最小闭环”
- 谈薪准备：期望范围 + 理由 + 底线（先不写在简历上）

## 5. 每日时间分配模板（建议 6-8 小时/天）

- 2.5-3h：主项目（功能/工程化/修 bug/补 README）
- 1.5h：Go 基础与后端基础（按高频主题复习）
- 1h：刷题（1 题精做 + 复盘）
- 0.5h：投递与跟进（固定每天做，不攒）
- 0.5h：复盘（记录卡点、明日安排）

## 6. 简历写法（最短路径）

### 技能栈写法（贴合 JD 关键词）

- Golang：熟悉 goroutine/channel、context、常用标准库（net/http、encoding/json 等）
- Web：熟悉 REST API 设计、JWT 鉴权、中间件、请求链路日志
- 数据库：MySQL 基础（索引、事务、慢 SQL 排查），Redis 基础（缓存策略）
- 工具：Git、Linux 常用命令、Docker 基础

### 项目描述公式

每个项目 3-5 行，推荐结构：

- 背景：做什么系统/解决什么问题
- 职责：你做了哪些模块（避免“参与”）
- 难点：你解决了什么技术点（缓存/索引/并发/幂等等）
- 结果：用数据表达（接口响应、QPS、减少 DB 查询次数、错误率下降等，没有数据就用“提升/降低”+依据说明）

示例句式（按你实际情况替换）：

- 基于 Gin + MySQL + Redis 实现待办管理 API，完成用户注册登录、JWT 鉴权与核心业务 CRUD
- 为列表查询设计联合索引并通过 EXPLAIN 验证，减少全表扫描并优化分页查询
- 为高频读取接口加入 Redis 缓存（TTL + 主动失效），降低数据库压力并提升响应稳定性

## 9. 高频题目清单（按优先级）

### Go

- slice 与数组区别、扩容与拷贝
- map 底层与并发安全、如何安全读写
- channel 用法、关闭规则、阻塞场景
- goroutine 泄漏常见原因与避免方式
- context 的传递与取消、超时控制

### HTTP/工程

- REST 设计、幂等性、状态码与错误码
- 中间件做什么（日志、鉴权、限流、recover）
- 超时与重试策略（在哪里做、怎么避免放大故障）

### MySQL/Redis

- 索引为什么快、什么情况下走不上索引
- 事务隔离级别、幻读/不可重复读概念
- 缓存策略：缓存穿透/击穿/雪崩的基本应对思路
